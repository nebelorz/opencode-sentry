## Context

See `proposal.md` for motivation and the delta specs for the behavior contract.

Current state (verified against the repository):

- `src/api/index.ts` is a Hono Worker with `GET /health`, `GET /api/v1/current`, and `GET /api/v1/changes`. It imports `latestSnapshot` and `latestChangeReport` from `src/api/data.ts`.
- `src/api/data.ts` statically imports the newest snapshot and newest change report; it is regenerated by `pnpm api:data`.
- `src/cli/api-data.ts` selects the newest snapshot and change report by lexicographic filename, validates both with the existing Zod schemas, and writes both `data/latest.json` (the pointer) and `src/api/data.ts` (the Worker bundle module).
- `wrangler.jsonc` points at `src/api/index.ts`; `package.json` has `build` (`wrangler deploy --dry-run`) and a local, uncommitted `deploy` script; `tsconfig.json` includes `@cloudflare/workers-types`; `eslint.config.js` ignores `.wrangler/**`; `pnpm-workspace.yaml` allows the `workerd` build.
- Tests: `tests/api/index.test.ts` and `tests/smoke.test.ts` cover the Worker; `tests/cli/api-data.test.ts` covers the pointer and module generation; `tests/fixtures/api/*.json` supplies valid and invalid snapshot/change fixtures.
- `data/latest.json` currently contains `{ "snapshot": "snapshots/...", "changes": "changes/..." }` and is tracked in Git.

Constraints: keep modules small; no database, no server, no new dependencies; keep history in Git; fail loudly; do not change collector, diff, or schema behavior.

## Goals / Non-Goals

**Goals:**

- Remove all undeployed Worker/API code, configuration, dependencies, and tests.
- Preserve `data/latest.json` as the stable pointer the OpenCode skill reads.
- Keep the existing snapshot and change-report validation for the pointer.
- Leave the main specs consistent through OpenSpec deltas.

**Non-Goals:**

- No HTTP endpoint, no Cloudflare account, no auth, no CORS, no caching headers.
- No change to collector, diff, schemas, CLI output for `collect`/`diff`, or data formats.
- No new abstraction beyond a renamed pointer command.

## Decisions

**1. Retire the capability instead of keeping it latent.**

The user chose raw Git as the integration interface. Keeping `hono`, `wrangler`, `@cloudflare/workers-types`, a `wrangler.jsonc`, and two test files for a feature that is never deployed contradicts the "smallest reliable system" and "avoid dead code" principles. The API is deleted rather than kept undeployed. Alternatives considered: keep the Worker buildable but undeployed (rejected: unused dependency and config surface with no consumer).

**2. Keep a pointer; rename the command to `latest`.**

The skill cannot enumerate directories over `raw.githubusercontent.com`, so it needs a stable entry point. `data/latest.json` already is that pointer. The `api:data` command is reduced to writing only the pointer and renamed to `latest` (`src/cli/latest.ts`), because the name `api:data` referred to a module that no longer exists. It keeps selecting the newest snapshot and change report by filename and validating both against the existing schemas.

**3. Stop generating `src/api/data.ts`.**

That module existed only so the Worker bundle could import the latest data. After removal nothing imports it. The pointer remains the single source of truth and is independent of any API.

**4. Spec deltas.**

`latest-pointer` is added as a new capability. `public-api` is retired by removing all of its requirements, so the archive deletes its main spec. The `project-scaffolding` requirement "Stub Cloudflare Worker builds" is removed because the Worker no longer exists.

**5. Cleanup of tooling leftovers.**

Drop `@cloudflare/workers-types` from `tsconfig.json` types, remove the `.wrangler/**` ignore from `eslint.config.js`, remove `.wrangler/` and `.dev.vars` from `.gitignore`, and remove `workerd` from `pnpm-workspace.yaml` `allowBuilds` while keeping `esbuild` (used by Vitest).

## Risks / Trade-offs

- If a public HTTP endpoint is wanted later, it must be rebuilt ([accepted]) -> raw GitHub already serves the data to the agent, so an endpoint is not on the roadmap.
- Renaming `api:data` to `latest` touches the delivery workflow -> the delivery workflow is rewritten in the sibling `scheduled-collection` change to call `pnpm latest`; apply `remove-public-api` first.
- Deleting fixtures used by two test files -> reuse `snapshot.valid.json` and `change-report.valid.json` under a neutral `tests/fixtures/latest/` directory and delete the invalid fixtures that only the Worker used.

## Migration Plan

1. Delete Worker/API sources, config, dependencies, and Worker tests.
2. Rename and reduce the pointer CLI and its test; move the valid fixtures.
3. Update `tsconfig.json`, `eslint.config.js`, `.gitignore`, `pnpm-workspace.yaml`, and `EXECUTIVE_SUMMARY.md`.
4. Rollback: restore `src/api/`, `wrangler.jsonc`, and the `api:data` script from Git history; data and pointer formats are unchanged.
